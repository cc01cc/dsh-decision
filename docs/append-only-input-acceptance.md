## 0. 结论先行

**写死总数 = 把时间漂移混进验收，必然假绿或假红。**

本仓的输入台账（`internal/A03-xihe/docs/lead-decisions-ledger.md`）是 append-only 活文档，其他 lane 一直在续写。2026-11-14 一次会话内实测它从 1,400,541 B 长到 1,466,942 B；同一套解析器在两份快照上分别得到 946 与 959 条 —— 任何「必须恰好 N 条」的判据都会在写下的当天就失效。

于是验收判据只保留三个可复算的要素：

| 要素 | 必须写清 | 反例（不许写） |
|---|---|---|
| **同快照** | 记录源文件 **字节数 + sha256**，双实现跑在同一份字节上 | 「现在跑一遍看是不是 946」 |
| **双实现** | 独立盘点器**不 import** 被测脚本，两边规则各自维护 | 用被测脚本自己算期望值 |
| **差集为空** | `独立盘点集合 ⊕ 迁移 uniqueEntries == ∅`，非空即红并点名缺号 | 「总数相等」（可被两边同错抵消） |

后果量（`over20k`、单条最大码点、污染占比）可以作为**附加**断言，但同样写成「≤ 阈值 / 不变量」，不写具体条数。

### 0.1 一句话边界：**差集为空 ≠ 归类正确**

差集校验的是**条目身份**（号有没有丢/多），**不校验内容归属**（谁的正文落在谁身上）。两者必须分开守：身份靠差集，归属靠夹具的**内容断言**（某标记串必须/不得出现在某号里）。

这不是理论洁癖，2026-11-14 当天就撞上了：快照 C 上差集 **∅**（959/959，前后两次修复都 ∅），但正文**错了两处**——`6e812ff` 让 `D-1044` 吞掉 `D-1046` 的 619 cp 执行条款（`D-1046` 从 2,314 cp 掉到 781 cp），另把 6 条附记正文各并了两遍（共重复 2,963 cp）。**只看差集的验收会把这批全放过去。** 详见 §6。

## 1. 为什么这三个要素缺一不可

- **缺「同快照」**：台账在两次测量之间被续写，差 7 条也说不清是缺陷还是新裁。本仓 2026-11-14 实测：两份快照的 uniqueEntries 是 944 / 951 / 955 / 959，但**差集恒为 {D-1375, D-1376}**——正是这一点把「可能是快照漂移」的辩解排除掉，缺陷才从「可能」变成「确定」。
- **缺「双实现」**：被测脚本的规则若是唯一参照，任何规则级缺陷都会被自己复现出来，差集永远是空。独立盘点器必须**另写一份**（哪怕规则相同），这样规则改动只落在一边，差集才会亮。
- **缺「差集为空」而只比总数**：总数相等可以掩盖「两边各错一处、正好抵消」。差集为空对**逐号**负责。

## 2. 怎么对 DSD 用这条口径

```text
快照   复制 internal/A03-xihe/docs/lead-decisions-ledger.md
       + internal/A03-xihe/docs/archive/lead-decisions-2026-11-05-to-2026-11-08.md
       到临时根，记录各自 字节数 + sha256
双实现 ① 迁移脚本：node packages/dsh-decision/scripts/migrate-ledger.mjs --dry-run --report <r.json>
       ② 独立盘点：标题（含多号/区间展开）∪ 项目符号 ∪ 粗体行首（含多号展开）∪ 表格行（cells>6），
          粗体附记（**D-n 附记/补记/附注/补注/勘误（…）**）不计新条目，归自己号
判据   set(①.caliber.externalIds) ⊖ set(②) == ∅；非空即红，打印缺号与多余号
附加   parseFailed == []；over20k == 0；单条最大码点 ≤ 20000
```

**判据不覆盖的东西**（避免过度宣称）：差集为空只保证「号不丢不多」，**不保证正文归属正确**。正文串条要用**内容断言**（某标记字符串必须/不得出现在某号里），这正是冻结夹具的作用——见 §3。

## 5. 已知不覆盖面（诚实边界）

1. **行内强调/续写不搬**：像 `**D-1046 执行条款（…）**` 这类「号 + 空格 + 短语 + （」的续写行，既不是条目也不在附记封闭集内，仍会落在当时打开的条目正文里（快照 C 实测 7 行 / 568 cp；`6e812ff` 时因 §6 的缺陷被放大成 9 行 / 1,187 cp）。判据上它们不造成条目缺失，也不造成超限，故**不列为缺陷**；要「落点回自己号」需要跨条搬移正文，与 append-only 语义冲突，需另行裁定。
2. **差集为空 ≠ 归类正确**：条目 kinds（heading/bullet/bold/row）与正文归属靠夹具的内容断言守，不靠差集。
3. **夹具只覆盖已实证的三种形态**：以后台账长出第四种静默丢弃形态时，先补一份合成夹具，再修脚本——顺序不能反（否则修完没有红态可证）。§6 就是这条纪律的反证：夹具 C 在修复**当天**就抓到了修复本身引入的新缺陷。

## 6. 夹具 C 抓到的那次「修一处坏一处」（2026-11-14 实证）

`6e812ff`（task-491 修复）把附记改成「flush 后自立为 current」，于是**附记那一刻的宿主条目被提前结束**，宿主在附记**之后**的正文被并进了附记所属号。快照 C 实测：

| 条目 | 改前 | `6e812ff` | 正解 |
|---|---|---|---|
| `D-1044` | 564 cp | **2,478 cp**（多出 `D-1046` 的 619 cp 执行条款） | 1,002 cp |
| `D-1046` | 2,314 cp | **781 cp**（丢了 `D-1046 执行条款` / `之二`） | 1,877 cp |

条目号差集始终为空（959/959），**只看差集发现不了这个缺陷**——它是「谁吞了谁的正文」，正是夹具 C 的内容断言守的那一格。另有一处纯重复：附记整行已含正文，再并 `bodyLines` 会把同一段并两遍（快照 C 实测 8 条附记共重复 2,963 cp；`D-1274` 3,495 → 2,521、`D-1272` 2,727 → 1,979）。

**正解两个改动，都在 `migrate-ledger.mjs`**：① 附记走「侧插」——直接落 `raw` 交给第二遍并入，**不 flush、不动 current**；② `mergeInto` 里附记只并 `headingLine`（整行已含正文），不再重复并 `bodyLines`。

**已落地**：A12 `e0a1cbbc`（8 增 4 删）。在快照 C 上复算：夹具 **3/3 绿**、差集 **∅（959/959）**、五条 cp 全部对上（1,002 / 1,877 / 2,521 / 1,979 / 1,197）、附记重复 **14 条 0 异常**、`over20k 0`、max 3,735、幂等 created 959 → 0。行内续写回落到 **7 行 / 568 cp**（缺陷 1 在时是 9 行 / 1,187 cp）。

> 纪律：**这类「修一处坏一处」只能靠内容断言抓**。所以 §0 的三要素之外，夹具必须有**反向断言**（某标记串**不得**出现在某号里），否则修法是「谁打开就塞给谁」还是「自立为 current」都照样绿。

**覆盖缺口的补课（2026-11-14 同日，dsd-2 报缺口、Lead 裁补）**：上面那两处缺陷只被夹具 C 守住一处。dsd-2 做了两条单独回退变异，读数暴露出**第二处没人守**：

| 变异 | 夹具（补 D 之前） | 实际后果 |
|---|---|---|
| 回退①：附记顶替 `current` | 红 1/3（夹具 C） | 宿主后文被带走 |
| 回退②：去掉 `mergeInto` 的附记去重 | **3/3 全绿** ❌ | `D-1044` 1,002→1,382 · `D-1274` 2,521→3,495 · `D-1272` 1,979→2,727 cp |

原因：A/B/C 三格验的是「正文**归谁**」，验不了「同一段正文**被并了几遍**」。补 `fixture-d-adjunct-dedupe.md` 后：**回退② ⇒ 只红 D**（断言 `occurs(rest) === 1`，实测报「出现 2 次」）；回退① ⇒ 只红 C，A/B/D 仍绿。

**这一格的探针必须取「正文本体（rest）」而不是标题里的标记串**——重复并入时被并两遍的是 rest（它是 `headingLine` 的子串）；拿标题标记测次数永远是 1，那就是个恒真的假判据（D-1205①）。

## 7. 接进 CI 的前置条件（写在这里，防止下一个人误判）

**本夹具接进 `pnpm test` / CI 的前提 = 它对 `HEAD` 绿。**

判断方法就一条命令（cwd=`packages/dsh-decision`）：

```
node --test tests/scripts/ledger-fixtures.test.mjs
```

- **绿** ⇒ 满足前置，可以接线。
- **红** ⇒ 先分清两种红，**不许直接当「测试坏了」跳过或删断言**：
  1. **真实缺陷**（本次 2026-11-14 就是这种）：失败信息点名「缺哪号 / 谁的正文跑到谁那里」，且用 `git show <上一版脚本>` 跑同一夹具能复现同样的红 ⇒ 是产品缺陷的证据，**修脚本，不修夹具**。
